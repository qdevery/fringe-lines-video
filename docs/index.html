01 · The big idea

Claude makes the editorial calls. Code does the pixels.

Asking an AI to click through an editor didn't work. It was slow, and it burned through our Descript credits. What works is splitting the job into three layers:

LAYER 1 · SKILLS

Recipes in plain English

One SKILL.md per format: what a good short looks like, how to pick a moment, pacing rules, QA checklist, honesty rules. Claude Code reads the right one automatically when you ask for that format.

LAYER 2 · SPECS

A small JSON file per piece

Claude reads the transcript and writes the decisions down: which seconds to use, the hook line, which graphic lands on which word, the slide copy. You can read it, tweak it and rebuild.

LAYER 3 · BUILDERS

Python, ffmpeg and Remotion

Deterministic scripts turn a spec into an MP4 or PNG: cutting, filler removal, camera switching, loudness, captions and animated graphics (React components rendered by Remotion).

Why this matters: if a render looks wrong, you fix one line of JSON and re-run. You don't redo the whole edit, and the AI never has to drive a mouse.

04 · How skills work

What a session actually looks like

A skill is a folder in .claude/skills/<name>/ containing a SKILL.md: a short description at the top, then the recipe. Claude Code sees the descriptions of every skill in the project. When your request matches one ("make a carousel"), it loads that recipe and follows it.

The recipes hold what we learned the hard way:

  • Taste: "never sit on a talking head for more than 6 s", "hook in 8–14 words".
  • Mechanics: which command to run and which JSON fields exist.
  • Guardrails: no host photos in carousels; on-screen numbers must match what was said; always name a source.
  • QA: make a contact sheet, check loudness, check for stray * characters, then report anything that needs a human check.

The project has five skills: editorial-short, howto-short, podcast-intro, carousel and infographic. They're mirrored in .agents/skills/ for other coding agents.

Gotchas we hit

Remotion "root component" timeout

Remotion must run from pipeline/remotion. render.mjs changes into that folder itself, so call it through the Python builders and not directly.

Long ffmpeg filter chains fall over on a 45-minute episode

The episode is rendered in segments and joined with the concat demuxer, not the concat filter. Lower-thirds are burned in per segment.

Google Drive and node_modules don't mix

setup.sh puts the Python venv in ~/.shorts-skill and node_modules in ~/.cache/fringe-lines-video, then symlinks them. Scratch renders (several GB) also live in ~/.cache.

Faster-whisper and PyAV 19

The transcriber decodes audio with ffmpeg instead of PyAV. It keeps "um" and "uh" on purpose, because the cutter needs to know where they are.

Times are on the Descript sequence clock

Every range and transcript time lines up with the exported XML and .txt. Each host's audio is offset by where its clip starts in the XML (the --offset flag).

07 · Sharing it on GitHub

Getting it into a public repo

The project is on GitHub at qdevery/fringe-lines-video. The code, skills and specs are small. The media isn't: the raw episode alone is about 7 GB, so it stays out.

Commit

  • pipeline/: the builders and the Remotion templates and fonts. All fonts are OFL.
  • .claude/skills/ and .agents/skills/
  • carousels/*/carousel.json and infographics/*/infographic.json as examples
  • work/<ep>/*.json specs (style, howto, episode) as worked examples
  • STATUS.md and this page (docs/index.html, which GitHub Pages can serve)

Leave out

  • inbox/: raw cameras, audio and screen shares
  • out/: rendered videos and images (attach them to a GitHub Release instead if you want to show them)
  • Clips, logs and caches under work/
  • reference/repos/: other people's repos, each under its own license
  • Optionally the word-level transcripts, if you'd rather not publish raw conversation
